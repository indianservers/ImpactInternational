Actual authority and login hierarchy

One organization: Impact International. The database contains 17 organizational roles and four committee roles. Platform authority is the server-owned Users.PlatformAdmin flag, independent of workspace role names. An Association Super Admin assignment without that flag does not unlock the premium dashboard.

International → National → Region → District → Zone → Club

PlatformAdmin flag → all recognized application permissions within the authorized organization context → premium platform dashboard. Otherwise: active owned workspace → role grants + permitted subtree → scoped dashboard. Committee membership adds only dated committee-specific authority.

Platform Super Admin, Platform Administrator, Organization Owner, Regional Governor and District Governor are not separate stored roles. Chairperson, Vice Chairperson, Member and Secretary are CommitteeRole relationships; Chairperson and Vice Chairperson can manage their committee. These relationships do not grant organizational administrator privileges.

Entry points: / and /login. Email/password is enabled during the explicitly requested local OTP pause. Server sessions validate expiry, ownership, membership validity, current appointments and the bound domain. Workspace switching replaces active scope; permissions are never combined across assignments. Production OTP defaults remain enabled.

Members may access the permitted scoped directory, member portal, their own membership and other granted features. Member-level directory permission is not permission to retrieve administrative intelligence. Financial accounting requires explicit financial-entity grants in addition to module permissions.

Implementation and metric integrity

The existing /api/v1/dashboard endpoint serves route descriptors, scoped aggregates and the platform view. ?view=platform and its CSV export require the authenticated platform flag on the server. Forged role identifiers, ancestor scopes and foreign workspaces cannot widen access. The browser URL /app/platform-dashboard has the same server gate.

The new navy-and-gold dashboard contains ten KPIs, seven priorities, membership and organization trends, event participation, club status, regional/district distributions, membership status, approval pipeline, officer coverage, renewal and engagement indicators, organization/club previews and eight administration links. Search, profile, theme and navigation reuse existing features. The bell links to actual governance priorities; no fabricated unread notification count is displayed.

Six date modes include custom dates. A repeatable-read database snapshot provides consistent aggregates. Queries project required columns and reuse existing tenant/organization indexes and services; no tables, role categories or competing analytics API were created. Counts use persisted records. Empty activities and undefined denominators are explicitly shown. Current stocks remain current; comparisons describe actual period activity rather than pretending historical stock snapshots exist. Historical renewal cohorts and dedicated approval timestamps are not reconstructed: definitions disclose the operational formulas and UpdatedAt-based turnaround.

The chart curves are SVG, generated from actual buckets; hover points show dates/counts. Date and distribution controls are interactive. Metric tooltips and the definitions panel disclose the comparison basis. A zero prior baseline shows no invented growth percentage.

Vulnerabilities discovered and fixed

  1. Privilege escalation through delegated roles: assignment creation read a role without loading its grant collection; an empty collection passed the subset check. It now loads grants before checking every requested permission against the delegator's held permissions. Regression tests reject a stronger role and a foreign-scope assignment.
  2. Audit information disclosure: the legacy dashboard returned recent audit records to users with organization.view. It now requires audit.view and scopes results. Member responses contain no administrative aggregates.
  3. Committee policy gaps: relationship-based detail and “mine” listing did not consistently check bound organization domain or active committee role. Both paths now check these constraints. Tests deactivate committee roles and verify that detail, listing and dashboard authority disappear immediately.
  4. Dashboard privilege boundary: premium analytics and CSV export now explicitly require PlatformAdmin; an Association Super Admin label alone is insufficient. Tests verify the distinction for all 17 stored role types.

Limits and outstanding considerations

This is a source review and executable authorization audit of dashboard routing, permission delegation, scoped APIs and committee relationships, not a formal proof of every state transition in every application module. The route inventory is a source index, not a claim that every listed handler received a penetration test. Explicit domain-tenant committee guards were reviewed in source; a real multi-domain deployment was not provisioned because the product is a single organization. No production load or 20,000-member benchmark was run. Existing historical data cannot provide exact past status snapshots or approval-decision timestamps; operational comparisons are disclosed. Amazon SES and WhatsApp remain unconfigured as previously requested. No known failing scenario remains in the recorded suite.
