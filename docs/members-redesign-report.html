Impact Members

Premium redesign · workflow and authorization verification · 13 November 2026

What changed

The Members page now follows the supplied navy, purple and gold reference. The existing routes, member forms, privacy rules, import process, lifecycle actions and authorization engine are reused.

  • Authorized sidebar submenus, desktop collapse, fixed Impact International organization context, mobile navigation and floating Add Member action.
  • Live status counts, six KPI cards, recorded-history membership trend, registrations/renewals, interactive regional distribution and explicit metric definitions.
  • Cascading region/district/zone/club filters; category, status, existing club-type, joined-date and renewal-date filters; existing profession, expertise, industry, location and current-office filters.
  • Readable list and photo cards, server sorting, pagination, column configuration, reorder/resize, sticky headers, quick preview and filtered/selected CSV and Excel exports.
  • Saved filters retain layout, columns, sort and view mode. Bulk status/category changes and reviewed transfer requests use existing per-record endpoints and show an explicit confirmation and per-record outcomes. Already matching records are skipped.
  • Existing Add Member popup retains photo upload, optional details, social links, duplicate review and automatic IDs. Profile gains contact, hierarchy and permission-gated history/workspace sections.
  • Guided import now includes a CSV template, eight visible stages and downloadable current-page error/review records. Original validation, duplicate resolution, preview, commit and idempotency remain intact.
  • Invitation popup supports up to 20 recipients, personal message, share link, QR and real acceptance/expiry tracking. Per-recipient failures are reported; successful invitations are retained.

Data integrity and scope

All counts and charts use database records. No mockup numbers or invented portraits were inserted into the UI. KPIs represent the authorized workspace; directory filters narrow the list and exports. Status/regional counts are membership records; total/active-member KPIs count distinct people. Historical active counts use MembershipHistory status and expiry at each bucket boundary. Growth compares first registrations across equal periods and does not fabricate a percentage when the baseline is zero.

The new filter helper is shared by the existing list and export APIs. District and zone identifiers are validated against the assigned subtree or its ancestors before intersecting scope. Member-directory privacy still applies. Current-office display and search use current officer appointments, not role labels. Financial entity grants and communication audience rules remain unchanged.

No schema migration or duplicate membership API/table was added for this redesign. Existing indexes, paging, debounced search, aggregate queries and cached reference options are retained. The browser receives at most the requested page, capped at 100 records; the normal UI requests 20.

Main database clubs_impact member records were preserved. Functional fixtures exist only in clubs_impact_dues_upgrade_20261113. A separate performance clone holds the synthetic 100,000-member dataset. The delivered port1234 preview remains attached to the normal QA/demo database.

Scope and remaining integration limits

Payment and communication sections link to their existing authorized workspaces; this change does not add a new cross-module member payment/message-history aggregation API. Card issuance and recipient-selection communication campaigns remain in ID Card Studio and Communication Center. Existing supported export formats are CSV and Excel; no unsupported PDF export is advertised. Printing applies to selected records on the currently loaded page.

Amazon SES/WhatsApp delivery remains pending the previously deferred provider setup. Tests verify queued/created invitations, links, intended-recipient acceptance, duplicate consumption prevention, revocation and expiry; they do not claim live email delivery. Import error downloads are explicitly labeled as the current review page. Performance covers a 100k local dataset with existing indexes; concurrent load and external providers require deployment-specific testing.
