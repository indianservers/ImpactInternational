# Phase 8 delivery report

Phase 8 core is implemented and locally verified. This is not a declaration that all eight phases, every aspirational example, or production release requirements are complete. The supplied attachment ends at section 9, “Support secure custom-domain onboarding.” No unseen sections were assumed.

## Delivered

- Unified, role-aware intelligence at `/app/intelligence`: current affiliations and distinct people, recorded starts, observed historical retention with explicit history-coverage warnings, configured hierarchy/countries/clubs, event participation, verified service hours/impact observations, required office coverage, communication delivery and shared governance completion. Date filters, authorized subtree drill-down, trends, CSV export and inspectable metric definitions use real SQL records.
- Native-currency financial summaries require explicit entity grants. Current receivables and dues are distinct fields. Affiliation counts are not unique people; verified people observations are not unique beneficiaries; delivery is not unique reach; governance completion is not regulatory compliance; independent books are not consolidated cash.
- Six allowlisted read-only assistant tools: general metrics, upcoming authorized events, own membership, own certificates, finance summaries/personal dues and authorized document retrieval. Local tools work without an AI account. The optional OpenAI Responses adapter only selects a tool: it receives the question and strict schemas, uses `store:false`, and never receives retrieved documents or financial facts. All data queries run locally under current permissions. It cannot approve, post, send campaigns or execute model-generated SQL.
- PDF knowledge indexing in the existing vault using PdfPig and PostgreSQL full-text search. Current version/hash, tenant, sharing/private/committee/meeting authorization and retention are revalidated before returning page excerpts and protected citations. Approved-only questions additionally check the matching approved request/hash. Stale derived passages are purged by the existing worker. Source text is untrusted evidence, never instructions.
- Advanced follow-ups extend the existing communication automation tables, worker, revisions and governance engine. Eight source triggers, exact conditions, Match/Otherwise branches, up to eight delayed steps, dry runs, independent approval, editable version-checked drafts, immutable reviewed versions, revision copies, execution traces, retries, cancellation and current-authority checks. Only generic creator notifications and administrative follow-up tasks are enabled. A single task producer, generated-task exclusion, per-version source keys and daily limits guard loops/duplicates. Queuing excludes processed sources before its bounded selection; delayed execution resolves its exact source instead of rescanning a first page.
- Universal search across members, organizations/clubs, officers, committees, events, meetings, tasks, projects, documents, own/authorized certificates and invoices. Literal search escaping, source permissions, bounded results, no private contact snippets, resource filters, workspace-specific recent searches and Ctrl-K UI.
- Root-managed association identity, logo/favicon, accent, terminology, language declarations, AI policy and feature availability. Public/login identity follows an activated custom host; the signed-in shell follows the active tenant. Feature policy subtracts backend permissions and filters shell navigation. Domain onboarding uses exact TXT ownership challenges; activation additionally requires a platform operator and configured, separately provisioned TLS/ingress host. Primary application hostname registration is rejected.
- Liveness/readiness, protected operator diagnostics, process request/error counters, queue failure counts, explicit release gates, updated OpenAPI/schema and expanded CI verification. No duplicate member, document, finance or workflow masters were introduced.

## Performance and operating bounds

`docs/phase8-scale.json` records the final warm sequential HTTP run on 101,035 people, 206,038 memberships, 101,009 invoices, 20,001 meetings, 50,000 tasks and 3,001 projects. Ten measured samples per case, one warm-up, shared development workstation; nearest-rank p95 for ten samples is the maximum. No distributed or concurrent-user SLO is inferred.

The final p95 values are approximately 3.70 seconds for the global dashboard, 120 ms for member search, 335 ms for task search and 2.54 seconds for all-source search. The global dashboard/general search still need query profiling and an agreed production latency target. A scope-materialization experiment did not improve measured latency and was reverted. Trigram/FTS and execution-due/generated-resource indexes are included; no arbitrary Redis/vector database was added.

Resource bounds are intentional: search 100 total hits with per-source caps, knowledge 40 revalidated candidates/5 excerpts, PDF 5 MB/100 pages/30k characters per page/1M text total/two parsers per process, dashboards top 50 club/entity summaries, up to 50 active rules per worker pass and 50 new sources/day/rule. These caps do not represent unlimited tenant fairness or very large workflow-fleet certification.

## Remaining scope and production gates

The initial audit remains the baseline inventory in `PHASE8_INITIAL_AUDIT.md`; the delivery above supersedes its Phase 8 “missing” entries. Earlier reports remain authoritative about unfinished advanced capabilities in their phases.

1. The unified dashboard is a shared scoped core, not every requested role-specific report. Full historical growth/activation/registration/volunteer/dues/collection ratios, cohort comparisons, club health/compliance policies and drillable operational registers need agreed source/denominator semantics and further implementation. Current catalog definitions must not be relabeled as these missing metrics. Historical hierarchy snapshots are unavailable; retention explicitly uses observed history.
2. The assistant does not yet implement every example question: specialized pending-application/committee summaries, declining-club comparisons, budget-versus-actual and regional impact ranking remain in existing modules or future vetted tools. It returns scoped facts/excerpts, not a general generative narrative. English keyword routing and lexical PDF retrieval have limited language/semantic recall. No OCR, antivirus, vector similarity, predictive ML or legal interpretation is claimed.
3. Workflow steps are bounded follow-ups, not a general graph/DAG engine, event bus, arbitrary webhook runner, election/approval automation or financial posting engine. Rules use a configured source window and exact-source current-state revalidation. Large active-rule fleets need fair scheduling/partitioned workers. Retry is operator initiated after failure; no external action is inferred from a generic follow-up task.
4. White-label identity/terminology is applied to the new experience and shell, not a complete translation of every historical screen/word. Supported languages are declarations, not translated UI bundles. Tenant theme presets, exhaustive terminology replacement, SaaS subscription billing and a full domain lifecycle (renewal/continuous ownership checks/automated ingress certificates) remain incomplete. Existing hierarchy, fiscal periods, categories, positions, sender verification and governance settings retain their own authorized modules.
5. Live AI calls, actual DNS delegation/TLS ingress and live email/WhatsApp/payment sandbox certification require external credentials/operator infrastructure. No live provider was contacted by the Phase 8 protocol tests. Store keys only server-side; never in browser/Vite configuration. Enable remote AI only after policy review and deliberate tenant opt-in.
6. Privileged MFA/SSO, off-host recovery/key portability, production container/TLS/failover execution, external monitoring/alerting, shared rate enforcement for scale-out, hardened PDF process isolation/malware scanning and broad accessibility review remain release blockers. Per-process telemetry/rate limits are disclosed. Feature switches restrict interactive permissions; committed background accounting/provider corrections are not represented as universally cancelled.

## Running and reviewing

Run the migrations with `dotnet run --project server --no-launch-profile -- --migrate`, then build with `npm run build`. See `.env.example` for optional server-only AI/domain/key/object settings; configure `PublicOrigin` to the actual primary host. Existing cookie/session, CSRF, tenant/workspace and source authorization continue to apply.

With an isolated seeded test API on port 5081, run `python tests/phase8.py`; run `python tests/phase8_providers.py` for self-contained loopback provider tests. On this Windows development setup, `python tests/phase8_recovery.py` performs the named isolated recovery/migration drill and `python tests/phase8_scale.py` targets the existing scale API on port 5088. Never run these fixture-mutating tests against production. The expanded GitHub workflow is saved as configuration only; a hosted CI run was not triggered or verified here.

See `docs/phase8-api.md`, `docs/openapi.json` and `docs/schema.sql` for interfaces/schema. All work remains uncommitted alongside the preserved Phase 7 changes; no deployment, commit or push was performed for this request.
